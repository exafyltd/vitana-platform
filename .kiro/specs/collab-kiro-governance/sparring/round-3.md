### R3-N1 [minor]

The plan introduces the `governance` field but never specifies that its VALUE must be validated (only `governance: owner` is legal). A.1 says the field is `governance: owner` and 'only valid with executor: kiro', A.2's validateLane change is described only at the path-glob level, and the Tests section covers 'the field on a claude lane or without executor: kiro' but never asserts an invalid value (e.g. `governance: bob`) is rejected. validateLane (queue.mjs:160-186) currently has no governance check at all, so the new A.2 allow-list must be written as `fm.governance === 'owner'` (strict). If an implementer instead writes a truthy/`!== undefined` guard, a kiro lane could declare `governance: anything` and reach governance paths. The PERM base-revision guard (A.3a) would still block *changing* the field, but the field-shape/allow check is the place that should reject a malformed value, and it is currently underspecified.
