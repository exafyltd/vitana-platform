Change types: Infrastructure/CI, Tooling/docs.
Outcome: the owner moves the delivery of both repositories (exafyltd/vitana-platform and exafyltd/vitana-v1) from GitHub to the self-hosted GitLab with one command once the checklist of plan §8.1 is green (`scripts/eng/delivery-cutover.sh apply agentic-delivery --mirror-account LOGIN`), and moves it back with one command (`scripts/eng/delivery-rollback.sh agentic-delivery`). `status` prints the 15 checklist items; `rehearse` runs the rehearsal of §8.1 step 5. Before any of this the settings sync runs the shadow pipelines (a project with a `cutover` block turns from `inactive` to `shadow` when its generated pipeline file reaches the CI folder), and the marker file turns both projects `live` (or `rehearsal`). Open PRs keep working through the bridge. Nothing runs by itself; every owner script has a dry run that changes nothing and refuses when a precondition is not met.
States: the checklist is not green (`apply` refuses and names the item); the plan slug is missing or wrong (nothing is called); the mirror account cannot push (refused before a change); the wrong AWS account or a missing tool (the script stops before it reads or changes anything); a re-run after the cut (every step says `already done`, no state-changing call); the kill switch is not on (exit 3, steps 1 to 5 stay done, the next run resumes at step 6); an API error mid-step (that step undoes its own changes and stops, nothing is half-done: steps 1, 2, 3, 4 and 8 are tested); the marker is set (native) and removed again (back to shadow); a rehearsal marker (shadow with `DELIVERY_MODE=live`); a rollback while GitHub main is not GitLab main or while a branch exists only on GitLab (refused, nothing restored); a rollback from a cut that stopped half way.
Surfaces: the settings sync on the GitLab host (`scripts/eng/gitlab-settings.mjs`, `infra/gitlab-engineering/settings/gitlab-settings.json`); GitHub settings of both repositories (branch protection, workflows, tags) through the owner's script; the owner's CloudShell; the pipeline runbooks agents read (`.kiro/pipeline/driver.md`, `lane-land.md`); Command Hub Delivery gets its events from other lanes. A deleted name can take seconds to be free, so `--break-lock` retries the create six times, 10 s apart. A dry run takes no lock. In `apply` the lock is taken after the checklist and before the first write, then the record is read again under the lock.

After step 1, item `protection-roundtrip` is red (the protection is the lock), so in practice such a cut can only be rolled back; the refusal names both ways.
