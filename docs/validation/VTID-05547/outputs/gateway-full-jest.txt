The 2 failures, and why:
  1. vtid-04226 "token provisioning script is dry-run by default": scripts/aws/setup-gateway-internal-token.sh calls openssl, which this sandbox does not have. Environmental; it fails identically on the lane base tree. CI runners have openssl.
  2. vtid-04814 "has exactly one screen per tab of NAVIGATION_CONFIG": caused by this lane. The Delivery module adds three tabs to NAVIGATION_CONFIG; the Command Hub voice-screen list (src/navigation/data/command-hub-screens.json) and its stored Titan vectors (nav-embeddings.bin/.json) are outside the lane paths, and the vectors need Bedrock credentials. See acceptance.md "Open items" and the patch handed over with the report.
  Note: AWS_REGION=eu-central-1 was set for the run because this sandbox exports another region, which fails test/providers/storage-provider.test.ts (it passes on the lane base tree with the region set). That is an environment difference, not a code difference.
