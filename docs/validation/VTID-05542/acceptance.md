Decisions taken inside the plan (for Gate 2):
- Tokens (plan §3.3): `bot-metrics` gets `read_api`; every other account `api` plus `write_repository` because they push over HTTPS. The `scopes` and `token_file` keys are part of schema v1. Every Developer or Maintainer account is made Reporter of `vitana/ci-config`, because a pipeline reads the central config with the triggering user's rights (M1 did the same for the mirror user).
- Branch protection (plan §3.3): on the Free tier only `allow_force_push` can be changed on a protected branch, so a changed access level means delete and re-create of `main` (retried once at once, then logged as `UNPROTECTED`).
- Squash and merge-commit message templates are both `%{title}`, which also covers the plan's §8 fallback. Merge settings of the `mirror` projects are left unmanaged, as M1 had them.
- Maintainer audit (plan §3.3): an unexpected Maintainer on a native project is reported (`check` exits 3) and never removed (`apply` exits 0).
- The legacy-runner pause is `runners.legacy.paused` in the file, `false` at the start (plan §3.1). The sync creates the `rehearsal` project with a README (plan §6 step 5).
- No webhook is configured at the start (plan §3.5); the hook is named `vitana-gateway` and its description carries a 12-character fingerprint of the signing token so a rotation is noticed.
- Order of a run: tokens are written last, after the retag, protections and memberships. A missing secret is created with `create-secret` (default AWS key) when `put-secret-value` finds none; the default key's policy lets account principals use it through Secrets Manager, so `settings.tf` has no KMS statement.
- The sync's admin token lifecycle (plan §3.3 leaves it open): first token minted by `ops-install.sh` with `gitlab-rails runner` (30 days, scope `api`), rotated by the sync under 10 days; a rotation that loses the new token makes the next run fail with 401 and say to run `m2.sh install`. A token minted per run was rejected: a Rails boot every 10 minutes is too heavy.
- Units: `ProtectSystem=full` with `ReadWritePaths=/etc/vitana` for the settings service only; Node pinned to 20.20.2 with its SHA256, linked at `/usr/bin/node` (the merge-bot and metrics units use that path); `MemoryMax` 512M, start timeouts 480 s and 120 s.
