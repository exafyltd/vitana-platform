Decisions taken inside the plan (for Gate 2):
- POST and PATCH are retried on 429 only (plan §3.7 says "retry on 429 and 5xx"; a repeated POST could post a second comment or create a second object). A PUT that is an action (merge, rebase) must pass `retries: 0` for that call. The merge-bot lane (VTID-05538, not built yet) must do so for `PUT …/merge` and re-read the merge request after an error before it decides the merge failed; this is recorded in that lane's log when it is built.
- A Retry-After longer than `maxDelayMs` is an error with `retryAfterMs`, not a clamped early retry: the caller (a timer-driven tool) decides when to try again.
- Redirects are never followed; a token shorter than 8 characters, or with characters outside `[A-Za-z0-9_.~=-]`, is refused (it could not be redacted reliably).
- A keyset `Link` on another origin than `baseUrl` is refused even when it is GitLab's own `external_url`: a client on the GitLab host that uses `http://127.0.0.1` paginates by offset, which is all the plan's lanes need.
- Not done, with the reason: an upper bound on `perPage` above 100 (GitLab's own maximum) and any `maxPages` default other than 1000 are left as they are; `OPTIONS` is not a supported method.
