 - **Recurrence guard (sized):** `<Avatar` appears 114 times in 86 files of src/components + src/pages; only 9 uses are `ClickableAvatar`. ### Track 3 — Phase C "smart"
**C1 Conflict warnings (VTID-6):** the add/edit/move screens show "overlaps with <your entry title>" or "busy (another calendar)" before saving. One new service function `findConflicts(userId, role, window)` composes exactly what the calendar screen composes: `listCalendarWindow` (own entries with recurrence expanded, other roles' title-less busy) **plus** `listExternalBusy` (the route's own second call, routes/calendar.ts:427) and returns overlaps; `GET /conflicts` is rewritten to call it. External busy is included as "busy (another calendar)", whatever `listExternalBusy` returns today, nothing more. Warning only, never blocks saving. No new status value. Own entries' titles only; other roles and external calendars appear as "busy", exactly as the calendar shows them today. DST/all-day cases covered by unit tests with fixed zones.
**C2 Find a time (VTID-7):** no new route: the existing `GET /events/gaps` (routes/calendar.ts:518, `getCalendarGaps` calendar-service.ts:182) gets optional `duration`, `from`, `to`, `limit` parameters and uses the same busy composition as `findConflicts` (so external busy counts) and the member's quiet hours instead of the hardcoded 07:00–22:00 (default unchanged when no quiet hours are set); a "Find a time" action in the add sheet shows up to 3 slots. Read-only.
**C3 Shared events / invites — design plan only (VTID-8):** produce the written design (attendee rows vs per-member copies, organizer-only edit/cancel with propagation, accept/decline, who sees whose answer, rate limits and block list, service-role bypasses RLS so every check is in code) and return it for its own Gate 1. **No code** in this plan. Reason: the privacy model decides everything else and needs the owner's choices.
**C4 Real two-way sync — not built; reasons recorded:** importing event titles from a member's private calendars changes the privacy model (today free/busy only), needs origin tagging to avoid push/import loops, new scopes for Outlook (Calendars.ReadWrite) and stored iCloud app passwords, and provider webhooks to scale beyond the polling caps. Free/busy-only stays the default; reconsider after C3. A status card for Outlook/iCloud (parity with GoogleSyncCard) is the only C4-adjacent item here, as part of C1's VTID.
