# VTID-04028 — W4d: stream the Operator Console turn over SSE with a live tool-call transcript (gap analysis §4.6)

Context: `docs/OPERATOR-CONSOLE-GAP-ANALYSIS-2026-09-17.md` §4.6 (Console UX) lists, first, "SSE streaming for the operator turn (the `/executions/:id/stream` pattern already exists); a tool-call transcript with args/result/duration". Until now `POST /api/v1/operator/chat` answered one JSON body after the whole turn — model call, every tool, the final model call — so a turn that read three files and tailed a log group showed a "Sending..." button for its whole duration and then one bubble; the tool activity lines (VTID-03822) appeared only afterwards, with no timings.

What ships:

- `processWithGemini()` gains an optional `onEvent` sink (`OperatorTurnEventSink`). Around the real tool loop it emits `model.turn` (stage `plan`/`final`, provider, model, tool count, duration), `tool.call` (index, name, args bounded to 1 200 chars) and `tool.result` (index, name, ok, duration_ms, clipped error, governance flag, result excerpt bounded to 600 chars). The sink is fire-and-forget: a throwing sink is caught and logged, and without a sink nothing is emitted.
- `routes/operator.ts`: the `/chat` handler body is now `runOperatorChatTurn(req, { onEvent?, threadId? })`, returning the status + body `/chat` always sent. `POST /chat` is unchanged (one JSON body, no sink). New `POST /chat/stream`: identical validation (400 JSON before any header), the same caller-authz marker, OASIS chat events, thread record (VTID-04022) and turn memory (VTID-04025) — framed as SSE: `turn.started` → `model.turn`/`tool.call`/`tool.result` → `reply` (exactly the `/chat` body) or `error` → `done`, with a 15 s heartbeat comment. Client-gone detection is on the response (`res.on('close')`), because on Node ≥ 16 the request's own `close` fires as soon as the JSON body is consumed.
- Command Hub (`app.js`): `sendChatMessage()` → `requestOperatorTurn()` → `streamOperatorTurn()` POSTs `/chat/stream`, reads the fetch body as a stream, parses SSE frames by blank line (heartbeat comments ignored, non-JSON tolerated), applies `tool.call`/`tool.result` to `state.chatLiveTranscript` and re-renders; `renderOperatorChat()` shows the live transcript under the messages while `chatSending` (running lines pulse, done lines carry `✓ · 1.2s`, failures `✗ — error`). The final message keeps the measured `duration_ms` on its activity lines. Fallback to `/chat` only when no stream can be obtained (404 or a non-event-stream response) — never after a turn already ran. `index.html` cache-bust bumped; `styles.css` gains the live-transcript states.

AC-1 — `processWithGemini` emits `model.turn(plan)` → `tool.call` → `tool.result` → `model.turn(final)` around a real tool round (run_code in the vm sandbox), with provider/model/timings, bounded args and excerpt; a failing tool is reported `ok:false` with its error; a throwing sink never breaks the turn; no tool call → only `model.turn(plan)`; no sink → no emission.
