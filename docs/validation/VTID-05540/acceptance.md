# VTID-05540 acceptance (eng-gitlab-m2/rehearsal)
Change types: Tooling/docs, Integration.
Outcome: one command shows whether the whole path (agents, fleet, merge bot, `main`) works on a scratch project before any real repository depends on it: `node scripts/eng/rehearse.mjs --project rehearsal --agents 12` (what `m2.sh rehearse` runs on the GitLab machine) puts a seed on `main` through the bot, opens 5 control and 12 lane merge requests from the four seat accounts, plays the reviewer as `agent-reviewer`, waits for `bot-land`, and prints a report whose verdicts are the acceptance A1, A2, A3, A4 and A8 of plan §9. Exit 0 only when all five held.
States: the project is not marked `rehearsal`, is mirrored, has a webhook (file or live), or main is not the native profile: refuses to start, exit 2, nothing written. A job stuck: the report names it (job id, status, merge request). The fleet does not scale: the report shows the machine launches AWS refused with its message and fails A1. The bot does not land: the report lists each unlanded lane with every reason the bot gave. The seed does not land (25 minutes) or GitLab shows no push event for the reviewer's commit (2 minutes): the run stops there, opens nothing else, still prints the report. The AWS role cannot read the fleet group: A1 NOT PROVEN naming the two IAM actions, the rest is decided.
Surfaces: the project `vitana/rehearsal` (four writes: commit, open and close a merge request, delete a branch) and the ASG `vitana-eng-fleet` (describe only). AWS: the seven token secrets `vitana/engineering/gitlab/agents/<username>`, read only. Nothing else, nowhere else. Locales and accessibility: n/a (infra and tooling, no user-visible string).
Contract: plan §3.8 and the A1 to A4 and A8 definitions of §9. The report format is documented in the header of `scripts/eng/rehearse.mjs` and in `infra/gitlab-engineering/rehearsal/README.md`. - D2 (§9 A4). Five control merge requests besides the 12 lanes, one for each refusal the plan names. "No current review" is two controls (no review at all, and a review made stale by a later code change), because the bot gives different reasons.
- D3 (§3.4). The collab tooling is copied to `tools/collab/`, not `scripts/collab/`: `queue.mjs` and `protected-gate-files.json` are protected gate files and the bot would refuse the seed merge request.
- D4 (§3.4). The reviewer's and the builders' commits are made through the Commits API with their own tokens (no clone, no git credentials). The bot trusts a review commit found in a push event of `agent-reviewer`; the script proves that event exists after the first review and otherwise stops with the reason. Not verified against a real GitLab (see below).
- D5 (task statement). Exit 2 is also a refusal to start: it always means nothing was written. Exit 1 means the run started.
- D6 (§9 A1). Peak fleet size is the most machines in the ASG in any state, the largest of the samples (every 15 seconds), and the report also gives how many were booting or serving. "Each job on its own machine" is machines launched >= jobs run from the activity history, as §9 says.
- D7 (§9 A1). The second wave (the reviews) is pushed once every first-wave job has started, so the pipelines overlap and the fleet can reach the plan's 20 machines with 12 merge requests; the central CI cannot be changed by this lane.
- D8 (§9 A8). A8 is decided from facts the rehearsal can see (no job on the legacy runner, the settings check clean); "paused after A1" is the owner's step and is only noted.
- D9 (§3.8). All reads are made with `bot-land` (the one account with the rights to read hooks, mirrors and protection) through a client with no write method; every write is made with the account that owns it.
- D10 (§9 A1). With `--agents` below 12 only the 20-machine peak is skipped (and the report says so).
- D11 (§3.8). A negative control that fails prints FAIL and does not fail the job, so the rest of the rehearsal still runs and the report decides.
- D12 (§3.8). `gitlab-host` tries 22, 80, 443 and 8080; a missing address of the machine is a FAIL, never a quiet pass.
- D13 (§3.4). The run closes merge requests left open by an earlier run (branch `rehearsal/…`) and refuses if any other merge request is open, because the bot would land it.
