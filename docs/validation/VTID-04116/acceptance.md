# VTID-04116 — Acceptance

RepoWise + Graphify codebase-intelligence tools were mandated by CLAUDE.md's
"Mandatory Codebase Intelligence Workflow" with neither tool ever installed
anywhere a session or the Operator Console could reach (flagged in this
repo's own CHANGE LOG, 2026-09-17, VTID-04002 gap analysis). This VTID closes
that gap for sessions (a SessionStart hook) and for the Operator Console (two
new `dev_*` tools).

AC-1: `repowise` and `graphify` are real, installable packages, verified by
actually installing and running them against this repo rather than trusting
their published descriptions.
TEST: manual (see commands.log) — `pip install repowise`, `uv tool install
graphifyy` both succeeded; `repowise init --no-prose -y` produced a real
75-page wiki + health report; `graphify update . --no-cluster` produced a
real 46,681-node / 90,186-edge graph. See outputs/repowise-graphify-run.md.

AC-2: A SessionStart hook installs and incrementally refreshes both tools'
indexes at the start of every Claude Code session on this repo, without
blocking session start on failure.
TEST: manual — `.claude/hooks/session-start-codeintel-setup.sh` was run
directly with `CLAUDE_CODE_REMOTE=true` in this session; each install/update
step is independently try/catch-guarded (`|| log "..."`) and the script
`exit 0`s unconditionally.

AC-3: The Operator Console gets two new read-only tools, `dev_repowise` and
`dev_graphify`, that shell out to the installed CLIs over a fixed,
allowlisted argv (never a shell string, never an arbitrary flag).
TEST: services/gateway/test/vtid-04116-operator-codeintel.test.ts — "accepts
only the documented repowise subcommands", "accepts only the documented
graphify subcommands", "graphify path splits into source/target argv, never
a shell string".

AC-4: Both new tools are gated behind `OPERATOR_CODEINTEL_ENABLED` and report
`not_configured` rather than erroring when the CLI binary isn't present in
the runtime (mirrors the existing `BEDROCK_ROLE_ARN`-unset contract) — this
PR ships inert on its own.
TEST: services/gateway/test/vtid-04116-operator-codeintel.test.ts — "refuses
both tools when OPERATOR_CODEINTEL_ENABLED is not \"true\"", "reports
not_configured when the binary is not installed (ENOENT), never throws".

AC-5: The change compiles and the existing gateway test suite is unaffected.
TEST: manual — `cd services/gateway && npx tsc --noEmit` clean (one
pre-existing, unrelated `@aws-sdk/client-cloudwatch-logs` module-resolution
error, not introduced by this PR); new suite 12/12 passing.

## Not done in this PR (flagged, not silently skipped)

- The gateway's own Docker image does not yet install `repowise`/`graphify`
  or ship a built index, so `dev_repowise`/`dev_graphify` report
  `not_configured` on every real deployment today. `OPERATOR_CODEINTEL_ENABLED`
  is also unset everywhere. Baking the CLIs + an index into the image (or an
  init-container step) and flipping the flag is a follow-up, owner-gated the
  same way `FISH_API_KEY`/`OPERATOR_SQL_READONLY_ENABLED` shipped inert
  before their secrets were provisioned.
- `.claude/CLAUDE.md`'s generated content (architecture map, health scores)
  is a point-in-time snapshot from this session's `repowise init` run; it is
  expected to be regenerated by the session-start hook on the next session
  and will drift between sessions on a repo this size — that is by design
  (same posture as the root `CLAUDE.md`'s own CHANGE LOG needing manual
  upkeep), not a defect.
